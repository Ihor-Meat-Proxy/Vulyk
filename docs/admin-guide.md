# Vulyk admin guide

## Production deploy

### Docker Compose (recommended starting point)

```bash
./scripts/install.sh prod --yes \
  --admin-email=admin@company.example \
  --admin-password='Str0ngPass' \
  --registration-mode=disabled
# generates .env.prod with random secrets + first-run settings; auth required
```

Stack file: [`docker-compose.prod.yml`](../docker-compose.prod.yml)

- Named volumes for Postgres data, backup mount, and attachments
- Healthchecks on `db`, `api`, and `web`
- `VULYK_AUTH_REQUIRED=true`, `VULYK_REGISTRATION_MODE=disabled`, `VULYK_SEED_DEMO=0` by default
- Optional env seed via `VULYK_ADMIN_EMAIL` / `VULYK_ADMIN_PASSWORD`, or:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod run --rm api \
  vulyk-api setup --yes
```

Dev/local stack: `./scripts/install.sh compose` (auth optional, demo seed on, registration open).

Full first-run paths: [guides/first-run-setup.md](guides/first-run-setup.md).

### Helm

```bash
# Validate render
./scripts/install.sh helm-template

# Install (create demo secrets — replace for real prod)
helm upgrade --install vulyk deploy/helm/vulyk \
  --namespace vulyk --create-namespace \
  --set secrets.create=true \
  --set auth.required=true \
  --set setup.adminPassword=change-me-admin12 \
  --set image.api=ghcr.io/ihor-meat-proxy/vulyk-api:0.2.0 \
  --set image.web=ghcr.io/ihor-meat-proxy/vulyk-web:0.2.0
```

Chart path: [`deploy/helm/vulyk`](../deploy/helm/vulyk). Auth is **required by default**. A setup Job runs `vulyk-api setup --yes`. Provide Secret keys:

| Key | Purpose |
|-----|---------|
| `DATABASE_URL` | Postgres URL |
| `VULYK_JWT_SECRET` | JWT / session signing |
| `VULYK_SECRETS_KEY` | Envelope encryption for LLM/integration/SSO secrets |
| `POSTGRES_PASSWORD` | Required when chart-managed Postgres is enabled |
| `VULYK_ADMIN_PASSWORD` | First-run admin (or use `setup.adminPasswordSecretRef`) |

Interactive fallback:

```bash
kubectl exec -it deploy/vulyk-vulyk-api -- vulyk-api setup
```

Raw manifests under [`deploy/kubernetes`](../deploy/kubernetes) are a minimal alternative.

### Bootstrap / default credentials

When seeded for local Compose (`VULYK_SEED_DEMO=1`):

| Account | Email | Password |
|---------|-------|----------|
| System admin | `admin@vulyk.local` | `VULYK_ADMIN_PASSWORD` in `.env` (generated by install.sh; must change when generated) |
| Demo user | `user@vulyk.local` | `VULYK_DEMO_PASSWORD` (default `vulyk-demo-user-1`) |

1. Complete first-run (env seed, setup Job/CLI, or web wizard + setup token).
2. Change the admin password if the default was used.
3. Explore the seeded sample projects (opt out with `VULYK_SEED_SAMPLE=0` or uncheck the wizard box; not seeded in prod unless enabled). Rows are flagged `is_sample` and show a **Sample** badge:
   - **Kyiv Open-Air Concert 2026** (`KYIV_CONCERT_2026`) — nested folders, ~35 cases with `KC-*` keys, requirements, dress rehearsal + ticketing smoke runs, and **Sample nightly #N** CI suites (creator **Sample CI**, varied outcomes).
   - **Vulyk QA** (`VULYK_QA`) — product self-coverage (~300 cases, prefix `VQA`; base seed + fragments under `backend/seed/vulyk-qa.d/`, including a 1:1 Playwright e2e suite), folders by area (setup, auth, RBAC, folders/tree, cases, runs, import, LLM, MCP, i18n/locales, header menus, appearance, PWA, performance, status badges & sample data, PDF, multi-repo CI, password policy, Admin Updates, lists/custom fields), requirements, and example runs. Cases link to Playwright specs via `external_key` where covered; planned gaps are `draft` with tag `planned`. See [`docs/testing/playwright-vulyk.md`](./testing/playwright-vulyk.md).
4. Create additional projects and memberships under gear → **Admin settings**.
5. Under **Admin → Settings → Sample data**, inspect what is installed, **Remove sample data** (confirm; deletes only `is_sample` rows; idempotent), or **Re-seed sample data**. System-admin only (`GET/DELETE /api/v1/admin/sample-data`, `POST /api/v1/admin/sample-data/reseed`).
6. Mint API tokens for CI/MCP (gear → **My settings**, or Admin → Tokens). Prefer `vulyk_at_…` personal tokens; project CI uses `vulyk_ci_…`.
7. Configure LLM providers, ALM integrations, [SSO](guides/sso.md), **Lists / Custom fields / Export·import**, and [content backups](guides/backup.md) as needed.
8. Set instance **default locale** (`en` / `uk` / `fr` / `es` / `de`) and theme under Admin settings (or `--locale` / `VULYK_DEFAULT_LOCALE` at first-run).

## Upgrades & backups

**Never run `docker compose down -v`** — `-v` deletes named volumes (Postgres data).

Preferred path: [guides/upgrade.md](guides/upgrade.md) (`./scripts/install.sh upgrade|backup|restore|rollback`).

For **portable project content** (cases, requirements, custom fields) to GitHub/GitLab/Nextcloud/Drive/local — not a full DB dump — see [guides/backup.md](guides/backup.md) and Admin → **Backups**.

### Compose / VM Postgres

```bash
# Via install script — verified directory bundle under ./backups/ (DB + env/secrets)
./scripts/install.sh backup
./scripts/install.sh restore ./backups/vulyk-VERSION-TIMESTAMP/ --yes
# Post-upgrade rollback (typed confirmation; see upgrade guide)
./scripts/install.sh rollback --confirm=ROLLBACK

# Or manual custom-format dump
docker compose -f docker-compose.prod.yml exec -T db \
  pg_dump -U vulyk -d vulyk -Fc > "vulyk-$(date +%F).dump"

docker compose -f docker-compose.prod.yml exec -T db \
  pg_restore -U vulyk -d vulyk --clean --if-exists < vulyk-YYYY-MM-DD.dump
```

Schedule dumps (cron/systemd timer) and copy artifacts off-box. The prod Compose file mounts `vulyk_pg_backup` at `/backup` inside the DB container for optional on-volume copies:

```bash
docker compose -f docker-compose.prod.yml exec db \
  pg_dump -U vulyk -d vulyk -Fc -f /backup/vulyk.dump
```

### Kubernetes

Take a logical dump (and preferably a VolumeSnapshot) **before** `helm upgrade`. The chart runs a pre-upgrade Job (`vulyk-api migrate run`). Postgres PVCs default to `helm.sh/resource-policy: keep` so uninstall does not delete data.

```bash
kubectl exec -n vulyk deploy/vulyk-postgresql -- \
  pg_dump -U vulyk -d vulyk -Fc > vulyk.dump
```

### What to backup

- PostgreSQL (required)
- Attachment volume/PVC if you store uploads outside the DB
- Secrets (`VULYK_JWT_SECRET`, `VULYK_SECRETS_KEY`) — without them encrypted integration/LLM/SSO keys cannot be decrypted

## Lists, custom fields & config export

### Option lists (Admin → Lists)

Reusable named value lists (e.g. **Browsers**, **Test type**, **Components**) with ordered items: label, optional key/value, colour, description, active/deprecated. Items that are in use are **deprecated** instead of hard-deleted. Only system admins manage lists; editors consume them via custom fields.

Sample seed creates a global **Browsers** list (Chrome, Firefox, Safari, Edge).

### Custom fields (Admin → Custom fields)

Field types: checkbox, dropdown / multi-select (from an option list), text, long text, number, date, URL.

Settings: name, key, entity (`test_case` / `requirement` / `both`), type, option list, default, required, help text, display order, show in list columns / filters, active.

**Scope**

- **All projects** — applied to every existing project and any project created later.
- **Selected projects** — pick projects now; for a new project, add the field later from **Fields available to add** (project custom-fields API) or Admin.

Per-project override of required/default is optional. Narrowing scope **hides** the field but **keeps stored values** (API warns; UI confirms with `acknowledge_hide_values`).

Values appear on case/requirement create/edit/detail, list columns & filters, bulk edit, case history snapshots, Chat/Generate context, importers (map external fields), and OpenAPI. Storage uses a typed JSONB values table with GIN / expression indexes for filtering at 20k+ cases.

RBAC: only **Admin** manages field definitions and lists; project editors set values (`CreateEditCases`).

Sample seed adds **Automated?** (checkbox) and **Browsers** (multi-select) with All-projects scope.

### Config export / import (Admin → Export / import)

Export a versioned JSON/YAML bundle (projects settings, custom fields + scopes, option lists, optional memberships by email, registration/SSO without secrets or passphrase-wrapped markers, LLM providers without keys, integrations without tokens, appearance defaults, locales/timezone, automation repos without tokens). Optionally include case/requirement/run data.

Import supports dry-run preview (create/update/conflict), merge or replace, mapping by key, idempotent apply.

```bash
# CLI
vulyk-api config export -o vulyk-config.json --format json
vulyk-api config import -i vulyk-config.json --dry-run
vulyk-api config import -i vulyk-config.json --yes --strategy merge

# install.sh wrappers
./scripts/install.sh config-export -o vulyk-config.json
./scripts/install.sh config-import -i vulyk-config.json --dry-run
```

API: `POST /api/v1/admin/config/export`, `/import/preview`, `/import` (system admin).

## Install script platforms

`scripts/install.sh` supports **Linux**, **macOS**, and **WSL2**. Native Windows is not supported — use WSL2. The script is written for **bash 3.2+** (macOS system bash) — avoid bash-4-only features; `./scripts/install.sh check` runs `bash -n` as a syntax self-check.

Modes: `compose`, `prod`, `dev`, `setup`, `check`, `helm-template`, `perf-smoke`, `upgrade`, `backup`, `restore`, `rollback`, `config-export`, `config-import`.

First-run flags: `--admin-email=`, `--admin-password=`, `--locale=en|uk|fr|es|de`, `--timezone=`, `--registration-mode=`, `--seed-demo=`, `--yes`.

Upgrade / release flags: `--version=X.Y.Z` (GHCR images), `--to=TAG|BRANCH`, `--no-backup`, `--yes`.
Rollback: `--confirm=ROLLBACK` (or `VULYK_ROLLBACK_CONFIRM=ROLLBACK`).

## Security-related environment

| Variable | Purpose |
|----------|---------|
| `VULYK_JWT_SECRET` | Required non-default value when auth is on (boot panics otherwise) |
| `VULYK_AUTH_REQUIRED` | Local default false; **fail-closed** when `VULYK_ENV=production\|prod` or https `VULYK_BASE_URL` (auto-on if unset; panic if explicitly false) |
| `VULYK_ENV` | Optional; `production`/`prod` enables auth fail-closed above |
| `VULYK_SECRETS_KEY` | Envelope encryption for LLM / integration / SSO / backup destination secrets |
| `VULYK_COOKIE_SECURE` | Force `Secure` on the session cookie (`1`/`true`) |
| `VULYK_EGRESS_ALLOW_PRIVATE` | Lab/tests only — allow private/link-local/metadata URLs and `file://` git; **never** in production |
| `VULYK_CONTENT_BACKUP_DIR` | Root for local content-backup destinations (default `./data/content-backups`) |
| `VULYK_REPO_CACHE` | Shallow clone cache for automation repos (default `/tmp/vulyk-repos`) |
| `VULYK_VERSION_BACKUP_DIR` / `VULYK_ROLLBACK_RETENTION_DAYS` / `VULYK_VERSION_BACKUP_COUNT` | Post-upgrade rollback points — [guides/upgrade.md](guides/upgrade.md) |

CI webhook secrets are **required** for webhook authorization; see [guides/ingest-and-ci.md](guides/ingest-and-ci.md). Full index: [README.md](README.md).

If Compose started without completing setup, re-run:

```bash
./scripts/install.sh setup --yes
```
