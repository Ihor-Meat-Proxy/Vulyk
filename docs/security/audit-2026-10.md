## Critical

### C1 — Headless API tokens authenticate as system admin

| | |
| --- | --- |
| **Severity** | Critical |
| **Evidence** | `backend/src/auth/extractor.rs:430-456` — null `user_id` → synthetic `is_system_admin: true`. `backend/src/routes/tokens.rs:61-66,136-140` — non-admins with `ManageApiTokens` can list/revoke null-user tokens. |
| **Impact** | Any legacy/open-mode token without `user_id` bypasses all RBAC (users, backups, SSO, settings). |
| **Fix** | Reject authentication for `user_id IS NULL` tokens (401). Migrate/bind existing rows to a real user or revoke them. Stop synthesizing admin principals. Require `user_id` on create when auth is on. |
| **Status** | Fixed in PR [#45](https://github.com/Ihor-Meat-Proxy/Vulyk/pull/45) |

### C2 — Unscoped CI webhooks authorize if any config lacks a secret

| | |
| --- | --- |
| **Severity** | Critical |
| **Evidence** | `backend/src/routes/webhooks.rs:86-98` (GitHub), `:159-169` (GitLab): `authorized = configs.iter().any(|c| c.webhook_secret.is_none())`. |
| **Impact** | One enabled config with `webhook_secret = NULL` makes unscoped `/api/v1/webhooks/github|gitlab` accept unsigned traffic and update dispatches. |
| **Fix** | Fail closed: require a secret; never treat missing secret as authorized. Prefer config-id webhook URLs. Reject create/update without secret when provider needs verification. |
| **Status** | Fixed in PR [#48](https://github.com/Ihor-Meat-Proxy/Vulyk/pull/48) |

### C3 — SSRF via automation Git remote URLs

| | |
| --- | --- |
| **Severity** | Critical |
| **Evidence** | `backend/src/services/automation_repo.rs:88-148` — `git clone` / `ls-remote` on arbitrary `remote_url` (incl. `file://`, RFC1918, link-local, cloud metadata). Create path: `backend/src/routes/automation_repos.rs`. |
| **Impact** | Authenticated users with repo manage can probe internal network / local FS via git. |
| **Fix** | Allow only `https://` (optional vetted `ssh://` hosts); resolve DNS and block private/link-local/metadata ranges; set `GIT_TERMINAL_PROMPT=0`; reject `file://`/`git://`. |
| **Status** | Fixed in PR [#59](https://github.com/Ihor-Meat-Proxy/Vulyk/pull/59) |

### C4 — SSRF via backup / ALM / LLM / SSO / CI base URLs

| | |
| --- | --- |
| **Severity** | Critical |
| **Evidence** | Backup: `backend/src/services/backup/destinations/{nextcloud,github,gitlab}.rs`. ALM: `backend/src/integrations/{openproject,jira_dc}.rs`. LLM: `backend/src/llm/providers/openai_compatible.rs`. SSO discovery: `backend/src/sso.rs` (~508+). CI `api_base`: `backend/src/integrations/github.rs`. `reqwest` follows redirects by default. |
| **Impact** | Server-side HTTP to attacker-controlled or internal URLs; redirect can pivot to metadata. |
| **Fix** | Shared egress validator (HTTPS-only, block private IPs after resolve, disable or re-validate redirects). Pin default API hosts unless enterprise allowlist. |
| **Status** | Fixed in PR [#59](https://github.com/Ihor-Meat-Proxy/Vulyk/pull/59) |

### C5 — CI provider tokens and webhook secrets returned in API JSON

| | |
| --- | --- |
| **Severity** | Critical |
| **Evidence** | `backend/src/models/ci.rs:7-18`; `backend/src/routes/ci.rs:63-71,109-123,134-148` serialize full `config` (GitHub `token`, GitLab `trigger_token`) and `webhook_secret`. Viewers and CI tokens with `ViewProject` receive them. |
| **Impact** | Cross-role secret disclosure; stolen viewer session → CI PAT + webhook secret. |
| **Fix** | Public DTO: strip secrets; expose `has_token` / `has_webhook_secret` only (mirror LLM/integrations). Encrypt at rest with `SecretsKey`. Never echo secrets on GET/create responses. |
| **Status** | Fixed in PR [#54](https://github.com/Ihor-Meat-Proxy/Vulyk/pull/54) |

## High

### H1 — Result history endpoints missing permission checks (IDOR)

| | |
| --- | --- |
| **Severity** | High |
| **Evidence** | `backend/src/routes/cases.rs:1136-1176` (`list_case_results_project`, `list_case_results_by_id`); `backend/src/routes/runs.rs:543-576` (item results + run history). No `OptionalAuthUser` / `require_permission`. |
| **Impact** | With auth on, any authenticated principal can read another project’s results if IDs are known. |
| **Fix** | Add `OptionalAuthUser` + `require_permission(..., ViewProject)`; for global case route resolve `project_id` from the case row. |
| **Status** | Fixed in PR [#50](https://github.com/Ihor-Meat-Proxy/Vulyk/pull/50) |

### H2 — `GET /api/v1/jobs/{id}` unscoped

| | |
| --- | --- |
| **Severity** | High |
| **Evidence** | `backend/src/routes/jobs.rs:24-28`. Job `payload` can include ingest content (`backend/src/models/job.rs`, enqueue in ingest). |
| **Impact** | Any auth’d (or anonymous if auth off) user can read arbitrary job payloads by UUID. |
| **Fix** | Require auth; authorize via `payload.project_id` / store `project_id` on the job; redact large content for non-owners. |
| **Status** | Fixed in PR [#50](https://github.com/Ihor-Meat-Proxy/Vulyk/pull/50) |

### H3 — Git stderr can leak embedded credentials

| | |

| **Evidence** | `backend/src/services/automation_repo.rs:52-84,135-148` — token embedded in remote URL; failures return stderr to client. |
| **Fix** | Prefer credential helper / `http.extraHeader`; redact `://user:pass@` and tokens in errors returned to clients. |
| **Status** | Fixed in PR [#59](https://github.com/Ihor-Meat-Proxy/Vulyk/pull/59) |

### H4 — Path traversal in automation repo indexing

| **Status** | Fixed in PR [#59](https://github.com/Ihor-Meat-Proxy/Vulyk/pull/59) |

### H5 — Local backup root is arbitrary filesystem path

| | |
| --- | --- |
| **Severity** | High |

| **Status** | Fixed in PR [#59](https://github.com/Ihor-Meat-Proxy/Vulyk/pull/59) |

### H6 — SSO `redirect_to` open redirect

| | |
| --- | --- |
| **Severity** | High |
| **Evidence** | `backend/src/routes/auth.rs:566-568` — accepts `starts_with('/')` (allows `//evil.example`) or loose base prefix. |
| **Fix** | Allow only same-origin absolute URLs under base, or relative paths matching `^/[^/]` (no `//`, `\`, scheme). |
| **Status** | Fixed in PR [#57](https://github.com/Ihor-Meat-Proxy/Vulyk/pull/57) |

### H7 — OIDC `id_token` not signature-verified

| | |
| --- | --- |
| **Severity** | High |
| **Evidence** | `backend/src/sso.rs:728-761,957-972` — base64 payload decode; `jwks_uri` unused for verify. |
| **Impact** | If an attacker can influence token endpoint responses (compromised IdP TLS, malicious issuer URL — related to C4), forged claims. |
| **Fix** | Verify JWT with JWKS (`iss`/`aud`/`exp`); do not trust unsigned claims. Prefer userinfo when JWKS unavailable. |
| **Status** | Fixed in PR (this change) — `verify_id_token` / JWKS fetch; unsigned `id_token` ignored in favour of userinfo |

### H8 — Password change does not invalidate sessions/JWTs

| | |
| --- | --- |
| **Severity** | High |
| **Evidence** | `backend/src/routes/auth.rs:448-459` updates hash only. Session TTL default 168h; JWT 12h. |
| **Fix** | `DELETE FROM sessions WHERE user_id = …` on password change/admin reset/disable. Consider short JWT TTL + refresh or denylist. |
| **Status** | Fixed in PR [#57](https://github.com/Ihor-Meat-Proxy/Vulyk/pull/57) |

### H9 — CI token permissions too broad + `create_project` hole

| | |
| --- | --- |
| **Severity** | High |

| **Fix** | Narrow CI to `UploadResults` (+ run-scoped reads). Reject `AuthVia::CiToken` / nil user on `create_project` and non-CI routes. |
| **Status** | Fixed in PR [#61](https://github.com/Ihor-Meat-Proxy/Vulyk/pull/61) |

### H10 — Insecure JWT / secrets defaults when env unset

## Medium

### M1 — Session cookie missing `Secure`

Evidence: `backend/src/routes/auth.rs:599-604`. Fix: set `.secure(true)` when TLS / `VULYK_COOKIE_SECURE` / https base URL.

### M2 — No CSRF token for cookie sessions

SameSite=Lax mitigates many cross-site POSTs; SPA also stores JWT in `localStorage` (`frontend/src/token.ts`). Fix: cookie-only + double-submit CSRF, or Bearer-only for API mutations.

### M3 — CORS `allow_origin(Any)`

Evidence: `backend/src/main.rs:118-128`. Fix: allowlist from `VULYK_BASE_URL` / `VULYK_CORS_ORIGINS` in production.

### M4 — No security headers (API or nginx)

Evidence: `backend/src/main.rs`; `frontend/nginx.conf`. Fix: CSP, HSTS (HTTPS), `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy` via `tower-http` + nginx `add_header`.

### M5 — Login throttle is process-local and IP-spoofable

Evidence: `backend/src/auth/login_throttle.rs`; `backend/src/routes/auth.rs:306-321` honors `X-Forwarded-For` without trusted-proxy config. Fix: persist (Redis/DB); key primarily by email; trust proxy hops.

### M6 — Attachment `entity_id` not bound to project

Evidence: `backend/src/routes/attachments.rs` create accepts any `entity_id`. Fix: resolve entity and assert project match.

### M7 — ALM integration secrets stored as plaintext JSON

Evidence: `backend/src/routes/integrations.rs` / `models/integration.rs` — API redacts (`has_secrets`) but DB column is plaintext unlike LLM/backups. Fix: envelope-encrypt with `SecretsKey`.

### M8 — Helm/Compose container hardening gaps

Evidence: Helm API deployment lacks `securityContext`; frontend nginx image runs as root (`frontend/Dockerfile`); updater mounts Docker socket (`docker-compose.prod.yml`). Fix: `runAsNonRoot`, drop caps, read-only root FS where possible; isolate updater.

### M9 — Rate limiting only on login

No global/API/ingest/LLM rate limits. Fix: `tower_governor` or equivalent on sensitive routes.

### M10 — Personal API tokens are full-user scope

Expected for personal tokens but high blast radius. Fix: optional project/scope claims.

### M11 — Attachment `Content-Type` user-controlled

Mitigated by `Content-Disposition: attachment`. Fix: MIME allowlist or force `application/octet-stream`.

### M12 — Gemini API key in query string

Evidence: `backend/src/llm/providers/gemini.rs`. Prefer header auth; avoid logging URLs.

### M13 — `zip` crate advisories (extract/symlink)

`cargo audit`: RUSTSEC-2026-0367/0368/0369 (Critical/High) on `zip 2.6.1`. Code uses `ZipWriter` + `ZipArchive::by_name("archive.json")` only — **does not call `extract()`**. Still upgrade when API-compatible (≥9) to clear advisory noise.

### M14 — Frontend transitive npm advisories via Lighthouse

`npm audit` in `frontend/`: high issues under `lighthouse` → `puppeteer-core` / `extract-zip` / etc. Dev/CI-only; e2e reports 0. Fix: bump lighthouse to ≥13.5 when CI allows.

## Low

### L1 — Password policy

Default min 16 (floor 12), letter+digit (`backend/src/auth/password.rs`). No breach-list / special-char requirement. Argon2id + dummy-hash timing are good.

### L2 — JWT carries `is_system_admin` claim

Authz reloads from DB (good). Prefer omitting privilege claims.

### L3 — `create_project` open to any authenticated user

By design for OSS; locked-down orgs may want admin-only.

### L4 — Admin disable/delete user does not clear sessions

Evidence: `backend/src/routes/users.rs`. Same fix as H8.

### L5 — Public importers / role matrix / health / OpenAPI

Intentionally public; low risk.

### L6 — Unmaintained transitive crates

`cargo audit` warnings: `encoding`, `lzw`, `rusttype`, `stb_truetype`, `stdweb` (via PDF stack). Track with PDF dependency upgrades.

### L7 — `rsa` / `crypto-bigint` / `lopdf` / `quick-xml` advisories

Indirect; no fixed `rsa` upgrade. Upgrade `lopdf`/`quick-xml` when PDF export deps allow.

### L8 — install.sh secret handling

Generates secrets and `chmod 600` on `.env` — good. Ensure `.env` never committed (`.gitignore` covers).

## Positive controls observed

- Argon2id password hashing; login always pays verify cost.
- Session / API / CI token secrets stored hashed.
- `must_change_password` enforced in middleware.
- Project-scoped SQL filters generally accompany permission checks.
- Integrations and LLM public DTOs redact secrets; LLM keys encrypted at rest.
- Attachments stored as DB bytes (not filesystem paths).
- API container runs as non-root `USER vulyk`.
- No `dangerouslySetInnerHTML` / HTML markdown renderer found in frontend (XSS surface small).
- Dynamic SQL fragments use column allowlists (`case_list`); values bound via SQLx.
